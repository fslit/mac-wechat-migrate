## 1. 开始前：先把这几件事定下来

### 1.1 三个必须先回答的问题

| 问题 | 为什么重要 |
|---|---|
| 两台电脑的微信版本号分别是多少？ | 4.0 是目录结构分水岭。两端不一致 → 先把旧的那台升到 4.0+，登录并**等数据升级完成**再操作 |
| 数据有多大？ | 决定目标盘空间需求。先用 `Cmd+I` 在访达里看，或跑 `du -sh <数据目录>`（海量小文件，可能要几分钟） |
| 是整机搬家，还是只搬微信？ | 整机搬家可以用系统「迁移助理」，见 [场景 C](#场景-c换新电脑)。只搬微信用本工具 |

### 1.2 目标盘空间

需要 **数据体积 × 1.2** 以上的可用空间（分片包 + 解包后的数据会短暂共存）。

```bash
df -h /Volumes/你的目标盘
```

### 1.3 网络或线材

按优先级选：

1. **雷雳线直连** —— 最快，且不经路由器，能绕开公司网络的隔离策略。必须是真雷雳线。
2. **SMB 共享盘（同一局域网）** —— 通用兜底。
3. **移动硬盘** —— 目标盘就是移动硬盘本身时最稳。

> ⚠️ 雷雳网桥的静态 IP **不要**和 Wi-Fi 用同一网段。同一网段时最长前缀匹配会让 Wi-Fi 抢走流量，表现为「昨天还好今天就连不上」。详见 [TROUBLESHOOTING](TROUBLESHOOTING.md#头号元凶雷雳网桥和-wi-fi-配到了同一网段)。

## 2. 确认微信版本与数据目录

在**两台电脑**上分别执行：

```bash
# 版本号
defaults read /Applications/WeChat.app/Contents/Info.plist CFBundleShortVersionString

# 数据目录（4.0+）
ls -la ~/Library/Containers/com.tencent.xinWeChat/Data/Documents

# 数据体积
du -sh ~/Library/Containers/com.tencent.xinWeChat/Data/Documents
```

预期看到 `app_data` 和 `xwechat_files` 两项。

> 如果 `Documents` 不存在，检查是否为 4.0 之前的旧结构：
> `~/Library/Containers/com.tencent.xinWeChat/Data/Library/Application Support/com.tencent.xinWeChat`

**两台版本不一致时**：先把低版本那台升级到 4.0+，登录微信并等它把数据升级完（期间不要操作），再继续。

## 场景 A：两台 Mac 同时在线，直传

### A.1 建立连接

**如果走雷雳线：**

1. 用**雷雳线**连接两台的雷雳口（不是随便一个 USB-C 口）。
2. 在**两台**上分别设置雷雳网桥静态 IP：
   - Mac 1：`系统设置 → 网络 → 雷雳网桥 → 详细信息… → TCP/IP → 配置 IPv4 选「手动」`
     IP `172.16.99.1`，掩码 `255.255.255.0`，路由器留空
   - Mac 2：同样操作，IP `172.16.99.2`
   - 命令行等价写法（需管理员密码）：
     ```bash
     sudo networksetup -setmanual "Thunderbolt Bridge" 172.16.99.1 255.255.255.0
     ```
3. 验证连通性：
   ```bash
   bash scripts/thunderbolt-check.sh 172.16.99.2
   ```
   重点看第 4 项（ping 通）和第 6 项（不冲突）。

**如果走 SMB：**

1. 在**要被搬走数据的那台（源机）**上：
   `系统设置 → 通用 → 共享 → 打开「文件共享」`
2. 点「共享文件夹」下方的 **+** 添加要共享的目录，权限给「读与写」。
   也可以整个共享用户主目录（更简洁）：共享 `~/`，然后靠账号权限控制。
3. **关键一步**：点右下角 **「选项…」** → 勾选 **「使用 SMB 共享文件」**，并在下方列表勾上允许通过 SMB 登录的账号。**这一步没勾，对端连不上。**
4. 窗口里会显示 **`smb://<IP>`** 或 **`smb://<主机名>.local`**，这就是对端要输入的地址。

**在目标机上挂载：**

1. 访达 → **前往 → 连接服务器**（`Cmd + K`）
2. 输入 `smb://172.16.99.1`（雷雳）或 `smb://<源机IP>`（局域网）
3. 身份选「注册用户」，名称填**源机的账号名**，密码填源机开机密码
4. 挂载后出现在访达边栏「位置」里

### A.2 探测目标盘能力

```bash
bash scripts/share_probe.sh "/Volumes/你的挂载点"
```

**重点看两项：**

- **硬链接支持** —— 如果显示 `✗`，记住：绝对不能从源机远程解包，必须到目标机本机跑 `wx_restore.sh`。
- **小文件写入速度** —— 如果明显偏慢（低于 300 个/秒），说明是延迟受限，务必坚持「先打包再传」，不要在共享盘上直接拷目录。

### A.3 源机导出

```bash
# 1) 完全退出微信
#    微信窗口 Cmd+Q，然后确认进程真的没了：
pgrep -x WeChat && echo "仍在运行，请再退一次" || echo "已退出"

# 2) 开跑（脚本自己也会检查微信是否退出）
python3 scripts/wx_export.py --dest "/Volumes/你的挂载点/微信数据迁移"
```

跑到一半断了、或手滑 `Ctrl+C` 了？**直接重跑同一条命令**，已完成的片自动跳过。

进度怎么看：

```bash
ls -lh "/Volumes/你的挂载点/微信数据迁移/chunks/" | wc -l   # 已传片数
tail -5 ~/.wx_export_work/export.log                        # 详细日志
```

### A.4 目标机解包

**登录到目标机（不是源机）**，然后：

```bash
# 1) 先确认数据在本地能访问（如果分片在另一台的共享盘上，先挂载/拷过来）
ls ~/微信数据迁移/chunks/ | head

# 2) 完全退出微信
pgrep -x WeChat && echo "仍在运行" || echo "已退出"

# 3) 解包（--verify 会先按 manifest 校验一遍，强烈建议加）
bash scripts/wx_restore.sh \
  --src ~/微信数据迁移/chunks \
  --dest ~/Library/Containers/com.tencent.xinWeChat/Data/Documents \
  --verify
```

脚本做的事：校验微信已退出 → 按 manifest 逐片核对 sha256 → 把目标目录里已有内容改名挪到 `_解包前旧数据-<时间戳>/`（不删除）→ 并发解包全部 64 片 → 打印体积与结果。

**如果分片是放在共享盘上、需要在目标机本机解包：**先把分片整体拷到目标机本地磁盘再解包，不要在共享盘上解包（SMB 不支持硬链接）。

## 场景 B：用移动硬盘中转

两台电脑不同时在线，或者不方便组网时用这个。

**硬盘格式很关键：用 APFS 或「Mac OS 扩展（日志式）」，不要用 exFAT。** exFAT 不保存扩展属性和符号链接，微信可能读不出记录。

```bash
# 1) 接上移动硬盘，确认挂载点
ls /Volumes/

# 2) 探测（此时应该显示硬链接支持 ✓，因为本地盘无此限制）
bash scripts/share_probe.sh "/Volumes/你的硬盘"

# 3) 源机导出
python3 scripts/wx_export.py --dest "/Volumes/你的硬盘/微信数据迁移"

# 4) 拔下硬盘，接到目标机

# 5) 目标机解包（微信先 Cmd+Q）
bash scripts/wx_restore.sh \
  --src "/Volumes/你的硬盘/微信数据迁移/chunks" \
  --dest ~/Library/Containers/com.tencent.xinWeChat/Data/Documents \
  --verify
```

也可以直接把分片拷到目标机本地磁盘再解包，通常比在移动硬盘上解包更快：

```bash
cp -R "/Volumes/你的硬盘/微信数据迁移/chunks" ~/微信数据迁移_chunks/
bash scripts/wx_restore.sh --src ~/微信数据迁移_chunks --dest ~/Library/.../Documents --verify
```

## 场景 C：换新电脑

如果目标机是**全新、还没设置过**的 Mac，直接用它自带的「迁移助理」最省事：整机用户目录一起过去，微信数据跟着走，不用碰任何目录。

1. 两台都接上雷雳线（走雷雳时迁移助理会自动吃满带宽）
2. 新 Mac 开机进入初始设置流程，在「从另一台 Mac 迁移数据」处选对应选项
3. 迁移完成后，**先别急着登录微信**，确认数据目录已就位再打开

**迁移助理的边界：**

- 目标机必须是**初始设置状态**（已经进过桌面的、被抹掉的机器也可以，但需要抹盘重来）
- 不适用于「只想搬微信、不想动其他数据」的情况 → 那种情况用[场景 A](#场景-a两台-mac-同时在线直传)

> **想直接拷盘抢救数据？** 源机开不了机时，可以进「共享磁盘」模式：Apple 芯片 Mac 关机 → 长按电源键进启动选项 → 选「共享磁盘」，然后通过雷雳从另一台机器访问它的整块磁盘，抢救性拷数据。

## 验证迁移结果

### 3.1 分片级校验（解包前或解包后都可用）

```bash
bash scripts/verify_manifest.sh /Volumes/你的挂载点/微信数据迁移
```

逐片核对**体积、条目数、sha256**三项。全过再解包。

### 3.2 解包后核对

```bash
W=~/Library/Containers/com.tencent.xinWeChat/Data/Documents
# 目标体积
du -sh "$W" "$W/app_data" "$W/xwechat_files"
# 目录结构
ls -la "$W"
```

与源机比较 `app_data` 和 `xwechat_files` 的体积，量级应当一致（微信自身可能在退出时清理部分缓存，少量差异正常）。

### 3.3 最终验证：打开微信

打开微信登录，逐项检查：

- [ ] 最近几个联系人的聊天记录能看到
- [ ] 聊天里的图片能打开、能滚动加载更早的
- [ ] 文件传输助手的文件能下载
- [ ] 群聊记录完整
- [ ] 搜索一个你确定存在的关键字，能搜到历史消息

**这五项都过了，才算迁移成功。**

## 收尾与清理

**确认微信一切正常之后**，再回收空间：

```bash
# 目标机：解包前的旧数据（确认新数据没问题才删）
rm -rf ~/Library/Containers/com.tencent.xinWeChat/Data/Documents/_解包前旧数据-*

# 目标机：分片包
rm -rf ~/微信数据迁移

# 源机：分片包 + 工作目录
rm -rf "/Volumes/你的挂载点/微信数据迁移"
rm -rf ~/.wx_export_work
```

如果希望**长期归档**而不是换机使用，用 Time Machine 整盘备份更稳，不必用这套脚本。

## 操作检查清单

打印出来照着划：

**源机**

- [ ] 确认微信版本 ≥ 4.0
- [ ] 目标盘可用空间 > 数据体积 × 1.2
- [ ] 跑过 `share_probe.sh`，知道目标盘是否支持硬链接
- [ ] 微信**完全退出**（`pgrep -x WeChat` 无输出）
- [ ] 跑 `wx_export.py --dest ...`
- [ ] 确认输出末尾是「成功 N / 失败 0」，且 `manifest.txt` 无 `MISSING`
- [ ] 让机器别睡眠（`系统设置 → 电池`，接电源时勾上「防止 Mac 自动进入睡眠」）

**目标机**

- [ ] 微信**完全退出**
- [ ] 微信至少登录过一次（`Documents` 目录已存在）
- [ ] `verify_manifest.sh` 全过
- [ ] 跑 `wx_restore.sh --src ... --dest ... --verify`
- [ ] 脚本末尾显示「已完成 64 / 64 片」
- [ ] 打开微信，五项验证全过
- [ ] 确认无误后才清理源数据与分片包
